Перенеси существующий сайт «Уральский контекст» на мой сервер и настрой дальнейшее обновление сайта из GitHub

Репозиторий: https://github.com/ctiv656-rgb/uralsky-kontekst
Рабочая ветка: server
Клонирование: git clone --branch server --single-branch https://github.com/ctiv656-rgb/uralsky-kontekst.git
Сначала полностью прочитай SERVER_GUIDE_RU.md, README.md и файлы deploy/ в этой ветке
Старая работающая версия: https://uralsky-kontekst.ctiv656.chatgpt.site/

Это уже существующий статический сайт, не создавай новый дизайн и не переписывай его на другой фреймворк
Сохрани все страницы, фотографии, прошлые сезоны, окно нового сезона, сетку и форму предложения темы

Сначала запроси у меня IP, ОС, SSH-пользователя и порт, домен, доступ к DNS, административный доступ и информацию о текущих сервисах сервера. Секреты и закрытые ключи получай только через защищённые средства среды, не через открытый чат. Сам по себе обычный чат ChatGPT не имеет SSH-доступа: используй подключённую среду с терминалом/доступом или дай мне команды для выполнения и проверяй результаты. Не утверждай, что развернул сайт, если доступ к серверу отсутствует

Для Ubuntu 24.04 используй подготовленную схему Nginx + systemd timer + ветка server. На другом сервере сначала адаптируй инструкцию. Проверь уже работающие сайты и порты, сохрани их конфигурации и не нарушай чужие сервисы

Размести сайт в корне выбранного домена, выпусти HTTPS, настрой пользователя context-deploy и /opt/uralsky-kontekst. Публикуй только результат deploy/build.py, не весь репозиторий

Настрой получение новых коммитов ветки server примерно раз в минуту через deploy/uralsky-kontekst-update.timer. Проверяй изменения до переключения current. Проверь автоматическое обновление реальным коммитом и сверкой __version.json. В дальнейшем все изменения этого сайта делай в данном репозитории и отправляй в server; новый основной домен должен вести на наш сервер. Публикации только в Sites и изменения только в main этот сервер не обновляют

Форма темы использует внешний Cloudflare Worker + D1 + Google Apps Script + закрытую Google Таблицу. Она не переезжает вместе с HTML. Добавь точный HTTPS-origin нового домена в ALLOWED_ORIGINS существующего Worker с разрешённым доступом владельца Cloudflare. Не создавай новую базу, не меняй существующие секреты, не подменяй IP и Origin через Nginx. Если доступа к Cloudflare нет, подготовь конкретное изменение для владельца и явно отметь, что форма ещё не подключена

Проверь страницы на телефоне и компьютере, оба формата нового сезона, старые сетки и прокрутку, HTTPS, отправку темы, появление строки в таблице, блокировку повторной темы за 24 часа и копирование ссылки. Тестовую тему отправляй после согласования. Не удаляй реальные записи из таблицы

Если требуется перенести и сервер формы в ту же инфраструктуру, сначала обозначь это как отдельную задачу, учитывая сохранение лимитов, очереди доставки, подписи Google и реального IP. Не выдавай статический перенос за перенос всей системы

После завершения сообщи новый URL, текущий SHA, состояние сертификата и таймера, результат проверки формы, где смотреть логи и как выполнить откат. Не отключай старый сайт до приёмки нового
