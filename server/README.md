## Состояние

Сервер развёрнут: https://liga-debatov-topics.ctiv656.workers.dev . Google Apps Script опубликован под аккаунтом ctiv656@gmail.com, таблица закрыта от посторонних. `topic-config.js` содержит только публичный адрес сервера. Ключи хранятся в Cloudflare Secrets и Script Properties, в репозитории их нет.

Проверена настоящая доставка через Worker в Google, категория «Экономика», пересчёт статистики и отказ 429 для второй темы с того же IP. Технические записи удаляются после проверок. Текст с кириллицей перед подписанием кодируется как ASCII JSON; иначе подписи Apps Script и Web Crypto расходятся из-за кодировки строки.

## Подключение после входа владельца в аккаунты

1. В Google Таблице открыть **Расширения → Apps Script**. Вставить `SheetsBridge.gs`.
2. В настройках проекта добавить свойство `BRIDGE_SECRET`: случайный секрет не короче 32 байт. Секреты генерируются в памяти при подключении, не попадают в этот репозиторий.
3. Развернуть Apps Script как веб-приложение: выполнять от имени владельца, доступ «Все». Сама таблица остаётся закрытой; endpoint принимает только подписанные сервером сообщения. Владельцу нужно подтвердить доступ скрипта к Google Sheets. Сохранить URL, заканчивающийся `/exec`.
4. Войти в Cloudflare через официальный Wrangler: `npx wrangler login`.
5. Из этой папки создать D1: `npx wrangler d1 create liga-debatov-topics`. Перенести возвращённый `database_id` в `wrangler.jsonc`.
6. Создать таблицы: `npx wrangler d1 execute liga-debatov-topics --remote --file=schema.sql`.
7. Через `npx wrangler secret put ИМЯ` передать три значения: `IP_SECRET` (отдельный случайный секрет), `BRIDGE_SECRET` (тот же, что в Google), `SHEETS_BRIDGE_URL` (URL `/exec`). Не писать значения в исходники или командную строку.
8. `npx wrangler deploy`. В `../topic-config.js` вписать только публичный HTTPS-адрес Worker в `window.TOPIC_API_BASE`, затем опубликовать сайт.
9. Проверить настоящую отправку, появление строки в таблице, пересчёт диаграммы, повтор с другим requestId (429), преждевременное повторение через статус. Проверочную строку убрать из рабочих данных после проверки. До живой проверки не считать интеграцию запущенной.

## Поведение

- Единственное обязательное поле — тема, 1–500 символов. Команда, автор и Telegram необязательны.
- Сервер читает `CF-Connecting-IP`, а не присланный формой IP. HMAC-отпечаток хранится в D1. Сырой IP и отпечаток в Google Таблицу не передаются.
- Атомарная резервация блокирует другой запрос с этого IP на **24 часа от принятой отправки**, независимо от даты, браузера и localStorage. Повтор того же запроса безопасен и не продлевает блокировку.
- Успех означает, что предложение сохранено: при временном сбое Google оно ждёт в outbox. Доставка повторяется каждые 5 минут; Apps Script проверяет ID под блокировкой и не создаёт дубликаты.
- После доставки личные поля удаляются из outbox; в Google Таблице остаются для организаторов. Отпечатки IP очищаются после истечения лимита с небольшим запасом. Не менять `IP_SECRET` при обычном развёртывании: смена обнулит распознавание действующих лимитов.
- Общая сеть означает общий лимит; VPN/новая сеть могут его обойти. Это ограничение по сети, а не доказательство личности. Для строгого лимита на одного человека потребуется вход в аккаунт.
- В «Категории» редактируются части слов через `|`. Больше совпадений — выше результат. При равенстве выигрывает более ранняя строка. Без совпадений — «Неразобрано». В «Темы» колонка H вручную меняет итоговую категорию через формулу I; диаграмма считает её автоматически.
- Рабочая ёмкость — 10 000 предложений; при заполнении расширить пределы и диапазоны. Доступ к персональным полям — только организаторам, таблицу не публиковать по общей ссылке.
